## 1. What is Fuzzing?

Fuzzing은 프로그램에 다양한 입력값을 반복적으로 전달하여 소프트웨어의 오류나 보안 취약점을 발견하는 자동화된 테스트 기법이다. 이때 퍼징을 수행하는 도구를 Fuzzer라고 한다.

일반적인 소프트웨어 테스트에서는 개발자가 예상할 수 있는 입력값을 중심으로 테스트를 진행하지만, 퍼징은 비정상적이거나 예상하지 못한 입력값까지 테스트하여 숨겨진 문제를 발견할 수 있다.

대표적으로 버퍼 오버플로우, 메모리 접근 오류, 프로그램 충돌 등의 문제를 발견하는 데 활용된다.

## 2. Fuzzing의 동작 원리

1. 테스트 대상 프로그램을 선정한다.
2. 테스트에 사용할 입력값을 생성하거나 기존 입력값을 변형한다.
3. 생성된 입력값을 프로그램에 전달하여 실행한다.
4. 프로그램의 충돌, 비정상 종료 등의 이상 동작을 확인한다.
5. 문제가 발생한 입력값을 저장하고 원인을 분석한다.

이러한 과정을 반복하면서 다양한 실행 경로와 잠재적인 취약점을 탐색한다.

## 3. Fuzzing의 종류

### 3.1. 프로그램 내부 정보에 따른 분류

**Black-box Fuzzing**

프로그램의 내부 구조나 실행 경로에 대한 정보 없이 입력값에 따른 실행 결과를 확인하는 방식이다. 소스 코드가 없어도 테스트할 수 있지만, 특정 실행 경로에 도달하기 어려울 수 있다.

**White-box Fuzzing**

프로그램의 내부 구조와 실행 조건을 분석하여 입력값을 생성하는 방식이다. Symbolic Execution 등의 기법을 활용하며, 복잡한 조건을 만족하는 입력값을 찾을 수 있지만 분석 비용이 높다.

**Grey-box Fuzzing**

프로그램의 코드 커버리지 등 일부 실행 정보를 활용하여 입력값을 생성하고 개선하는 방식이다. Black-box와 White-box사이의 중간 형태로, 효율적인 실행 경로 탐색이 가능하다.

### 3.2. 입력값 생성 방식에 따른 분류

**Mutation-based Fuzzing (변형 기반 퍼징)**

기존 입력값의 일부를 변경/삭제/추가하여 새로운 입력값을 생성하는 방식이다.

예를 들어 기존 입력값이 `ABCD`라면 `ABXD`, `ABC`, `ABCD12345` 등의 입력값을 생성할 수 있다.

**Generation-based Fuzzing (생성 기반 퍼징)**

파일 형식이나 프로토콜의 구조 및 규칙을 바탕으로 새로운 입력값을 생성하는 방식이다. 복잡한 데이터 형식을 테스트하는 데 유용하지만, 입력 데이터의 구조에 대한 사전 지식이 필요하다.

### 3.3. Coverage-guided Fuzzing

프로그램에서 어떤 코드가 실행되었는지를 나타내는 코드 커버리지를 기준으로 입력값을 개선하는 방식이다.

새로운 실행 경로를 발견한 입력값을 저장하고, 해당 입력값을 다시 활용하여 더 많은 실행 경로를 탐색한다.

단순히 무작위 입력값을 전달하는 것보다 프로그램 내부의 다양한 기능을 효율적으로 테스트할 수 있다는 장점이 있다.

## 4. 대표적인 Fuzzer

### 4.1. AFL++

AFL++(American Fuzzy Lop plus plus)는 기존 AFL을 기반으로 성능과 기능을 개선한 오픈소스 퍼저이다.

코드 커버리지를 활용하여 새로운 실행 경로를 발견하고, 기존 입력값을 변형하면서 반복적으로 테스트를 수행한다.

**주요 특징**

- Coverage-guided Fuzzing 방식 사용
- 다양한 입력값 변형 기법 지원
- 컴파일 과정에서 계측 가능
- QEMU 등을 활용하여 소스 코드가 없는 프로그램도 테스트 가능
- 사용자 정의 변형 기능 지원

주로 C/C++로 작성된 프로그램이나 바이너리의 취약점을 탐색하는 데 활용됨.

### 4.2. Jackalope

Jackalope는 Google Project Zero에서 공개한 바이너리 기반의 오픈소스 퍼저이다.

소스 코드가 없는 바이너리도 코드 커버리지를 기반으로 테스트할 수 있으며, 사용자 정의 기능과 분산 퍼징을 지원한다.

**주요 특징**

- Coverage-guided Fuzzing 방식 사용
- TinyInst를 활용한 바이너리 계측
- Windows, macOS, Linux, Android 지원
- 여러 스레드 또는 여러 컴퓨터를 활용한 병렬 테스트 가능
- 입력값 변형 및 전달 방식 등 사용자 정의 가능

특히 소스 코드를 확보하기 어려운 프로그램을 분석하거나, 여러 컴퓨터를 활용하여 퍼징을 수행할 때 유용하다.

### 4.3. LibFuzzer

LibFuzzer는 LLVM 기반의 Coverage-guided Fuzzer이다.

테스트 대상 코드와 함께 컴파일하여 동일한 프로세스 내부에서 특정 함수를 반복적으로 실행하는 방식으로 동작한다.

**주요 특징**

- Coverage-guided Fuzzing 방식 사용
- In-process Fuzzing 방식 사용
- 특정 함수 및 라이브러리 테스트에 적합
- AddressSanitizer 등과 함께 사용하여 메모리 오류 탐지 가능
- 프로세스를 매번 새로 생성하지 않아 빠른 반복 실행 가능

주로 소스 코드에 접근할 수 있는 C/C++ 프로그램의 특정 기능이나 라이브러리를 테스트하는 데 활용됨.

## 5. Fuzzer 비교

| 구분 | AFL++ | Jackalope | LibFuzzer |
| --- | --- | --- | --- |
| 탐색 방식 | Coverage-guided | Coverage-guided | Coverage-guided |
| 소스 코드 | 없어도 가능 | 없어도 가능 | 일반적으로 필요 |
| 주요 실행 방식 | 대상 프로그램 반복 실행 | 바이너리 계측 및 실행 | 동일 프로세스 내부에서 함수 반복 실행 |
| 주요 대상 | 프로그램 및 바이너리 | 소스 코드가 없는 바이너리 | 특정 함수 및 라이브러리 |
| 주요 장점 | 다양한 변형 및 계측 방식 | 사용자 정의 및 분산 퍼징 | 빠른 반복 실행 |
| 주요 제약 | 대상에 따른 환경 설정 필요 | 기본 변형 전략의 한계 | 테스트 대상 함수 작성 및 빌드 필요 |

=> 세 퍼저 모두 코드 커버리지를 활용하지만, 테스트 대상과 실행 방식에서 차이가 있다. 

소스 코드의 확보 여부/분석 대상/실행 환경 등을 고려하여 적절한 퍼저를 선택해야 한다.

## 6. Fuzzing의 장단점

### 장점

- 예상하지 못한 입력값에서 발생하는 오류를 발견할 수 있다.
- 사람이 직접 수행하는 테스트보다 많은 입력값을 테스트할 수 있다.
- 자동화된 반복 테스트가 가능하다.
- 소프트웨어 개발 단계에서 잠재적인 보안 취약점을 발견할 수 있다.

### 단점

- 복잡한 입력 조건을 만족하기 어려울 수 있다.
- 발견된 오류가 실제 보안 취약점인지 추가적인 분석이 필요하다.
- 모든 실행 경로를 탐색한다는 보장이 없다.
- 테스트 과정에서 많은 시간과 컴퓨팅 자원이 필요할 수 있다.

## 7. 요약

퍼징은 다양한 입력값을 자동으로 테스트하여 프로그램의 오류와 잠재적인 보안 취약점을 발견하는 기법이다.

퍼저마다 지원하는 실행 환경과 테스트 방식이 다르기 때문에 분석 대상의 특성에 따라 적절한 도구를 선택하는 것이 중요하다고 생각했다.
