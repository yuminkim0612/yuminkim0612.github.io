## 1. IDS/IPS ?

IDS와 IPS는 네트워크나 시스템에서 발생하는 비정상적인 활동과 보안 위협을 탐지하기 위한 보안 시스템이다.

- **IDS(Intrusion Detection System)**: 침입 탐지 시스템으로, 의심스러운 활동을 탐지하고 관리자에게 경고를 전달한다.
- **IPS(Intrusion Prevention System)**: 침입 방지 시스템으로, 의심스러운 활동을 탐지하고 공격으로 판단된 트래픽을 차단한다.

두 시스템의 가장 큰 차이점은 공격을 직접 차단하는지의 여부이다.

## 2. 동작 원리

### 2.1. IDS

1. 네트워크 트래픽이나 시스템 로그를 수집한다.
2. 수집한 데이터를 분석하여 비정상적인 활동을 탐지한다.
3. 공격으로 의심되는 활동이 발견되면 관리자에게 경고를 전달한다.
4. 관리자가 경고 내용을 확인하고 필요한 대응을 수행한다.

IDS는 기본적으로 공격을 직접 차단하지 않고 탐지와 경고에 집중한다.

### 2.2. IPS

1. 네트워크를 통과하는 트래픽을 실시간으로 검사한다.
2. 공격 패턴이나 비정상적인 활동을 탐지한다.
3. 공격으로 판단된 패킷을 폐기하거나 연결을 차단한다.
4. 탐지 및 차단 내용을 기록하고 관리자에게 전달한다.

IPS는 일반적으로 트래픽이 직접 통과하는 경로에 설치되어 공격에 즉각적으로 대응할 수 있다.

## 3. IDS와 IPS의 유형

### 3.1. 설치 위치에 따른 분류

| 유형 | 설명 |
|---|---|
| NIDS | 네트워크 트래픽을 분석하여 침입을 탐지한다. |
| HIDS | 개별 호스트의 로그, 파일 변경, 시스템 활동 등을 분석한다. |
| NIPS | 네트워크 트래픽을 검사하고 악성 트래픽을 차단한다. |
| HIPS | 개별 호스트에서 발생하는 악성 행위를 탐지하고 차단한다. |

NIDS와 NIPS는 네트워크를 중심으로 동작하며, HIDS와 HIPS는 개별 서버나 컴퓨터를 중심으로 동작한다.

### 3.2. 탐지 방식에 따른 분류

**시그니처 기반 탐지(Signature-based Detection)**

이미 알려진 공격 패턴을 저장해 두고 수집한 데이터와 비교하는 방식이다. 알려진 공격을 탐지하는 데 효과적이지만 새로운 공격이나 변형된 공격을 탐지하기 어려울 수 있다.

**이상 행위 기반 탐지(Anomaly-based Detection)**

정상적인 시스템이나 네트워크의 행동을 기준으로 평소와 다른 활동을 탐지하는 방식이다. 알려지지 않은 공격도 탐지할 가능성이 있지만 정상적인 활동을 공격으로 판단할 수 있다.

**상태 기반 프로토콜 분석(Stateful Protocol Analysis)**

네트워크 프로토콜의 정상적인 동작 방식과 실제 통신 상태를 비교하여 비정상적인 통신을 탐지하는 방식이다.

## 4. 활용 방법

IDS와 IPS는 기업 내부 네트워크, 서버, 데이터센터 등 다양한 환경에서 활용된다.

- 비정상적인 네트워크 트래픽 탐지
- 악성코드 관련 통신 탐지 및 차단
- 포트 스캔과 같은 공격 징후 탐지
- 시스템 파일의 비정상적인 변경 감시
- 알려진 취약점을 악용하는 공격 탐지 및 차단
- 보안 사고 분석을 위한 로그 수집

대표적인 도구로는 Snort, Suricata, OSSEC 등이 있다. Snort와 Suricata는 네트워크 기반 침입 탐지 및 방지에 활용되며, OSSEC은 호스트 기반 침입 탐지에 활용된다.

## 5. IDS와 IPS의 장단점

| 구분 | IDS | IPS |
|---|---|---|
| 장점 | 공격 징후를 파악하고 분석할 수 있음 | 공격에 실시간으로 대응할 수 있음 |
| 장점 | 정상 트래픽을 직접 차단하지 않음 | 관리자의 개입 없이 자동 차단 가능 |
| 단점 | 공격을 직접 차단하지 못함 | 정상 트래픽을 잘못 차단할 수 있음 |
| 단점 | 관리자의 추가 대응이 필요함 | 네트워크 성능에 영향을 줄 수 있음 |

두 시스템 모두 정상적인 활동을 공격으로 판단하는 오탐(False Positive)과 실제 공격을 탐지하지 못하는 미탐(False Negative)이 발생할 수 있다.

따라서 탐지 규칙을 지속적으로 업데이트하고 운영 환경에 맞게 설정을 조정해야 한다.

## 6. IDS와 IPS의 차이점

| 비교 항목 | IDS | IPS |
|---|---|---|
| 주요 목적 | 침입 탐지 | 침입 탐지 및 방지 |
| 공격 대응 | 경고 및 로그 기록 | 자동 차단 및 로그 기록 |
| 설치 방식 | 주로 복제된 트래픽 분석 | 주로 트래픽 경로에 직접 설치 |
| 대응 주체 | 관리자 | 시스템의 자동 대응 |
| 오탐 발생 시 | 불필요한 경고 발생 | 정상적인 통신이 차단될 수 있음 |

쉽게 말하면 IDS는 침입자를 발견하고 경고하는 CCTV와 같고, IPS는 침입자를 발견하고 출입까지 차단하는 보안 장치와 같다.

## 7. 학습 후 느낀 점

IDS와 IPS를 공부하면서 공격을 탐지하는 것뿐만 아니라 탐지 이후 어떻게 대응하는지도 중요하다는 것을 알게 되었다.

IPS는 공격을 자동으로 차단할 수 있다는 장점이 있지만, 정상적인 트래픽까지 차단할 가능성이 있기 때문에 무조건 IDS보다 좋은 시스템이라고 할 수는 없다.

따라서 시스템의 목적과 운영 환경에 따라 적절한 방식을 선택하고, 탐지 규칙을 지속적으로 관리하는 것이 중요하다고 생각한다.
