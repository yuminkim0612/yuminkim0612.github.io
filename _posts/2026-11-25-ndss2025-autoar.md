## 1. 논문 정보

- **제목:** Silence False Alarms: Identifying Anti-Reentrancy Patterns on Ethereum to Refine Smart Contract Reentrancy Detection
- **컨퍼런스:** NDSS Symposium 2025
- **연구 분야:** 스마트 컨트랙트 보안, 재진입 취약점 탐지
- **논문 원문:** [논문원본 PDF](https://www.ndss-symposium.org/wp-content/uploads/2025-167-paper.pdf)

## 2. 논문 선정 이유 및 문제 요약

이전에 Curve Finance 해킹 사건을 분석하면서 스마트 컨트랙트의 재진입 취약점과 방어 방식에 대해 공부했었다. 해당 사건에서는 재진입 방지 장치가 구현되어 있었음에도 컴파일러의 결함으로 인해 공격이 발생했다. 이를 계기로 재진입 취약점을 탐지하는 기술과 기존 탐지 방식의 한계에 대해 더 알아보고자 해당 논문을 선정했다.

- **해당 논문에서 다루는 문제:** 기존 재진입 취약점 탐지 도구가 안전한 코드까지 취약하다고 판단하는 오탐(False Positive) 문제
- **문제 해결이 필요한 이유:** 불필요한 경고가 많아질수록 보안 분석에 필요한 시간과 비용이 증가함

## 3. 배경 및 문제 정의

### 3.1. 재진입 공격(Reentrancy Attack)

재진입 공격은 스마트 컨트랙트가 외부 컨트랙트를 호출하는 과정에서 기존 함수의 실행이 끝나기 전에 다시 해당 컨트랙트의 함수가 호출되면서 발생하는 공격이다.

예를 들어 사용자의 잔액을 차감하기 전에 자산을 전송하도록 구현된 컨트랙트가 있다고 가정해보자. 공격자는 자산을 전송받는 과정에서 출금 함수를 다시 호출할 수 있다. 이때 내부 잔액이 아직 갱신되지 않았다면 기존 잔액을 기준으로 출금이 다시 이루어질 수 있다.

이러한 재진입 공격은 동일한 함수를 반복적으로 호출하는 방식뿐만 아니라 서로 다른 함수를 호출하는 Cross-Function Reentrancy 형태로도 발생할 수 있다.

스마트 컨트랙트는 실제 자산을 관리하기 때문에 이러한 취약점이 큰 금전적 손실로 이어질 수 있다.

### 3.2. 재진입 공격 방어 방식

재진입 공격을 방지하기 위한 대표적인 방법에는 CEI 패턴과 Reentrancy Guard가 있다.

#### CEI(Checks-Effects-Interactions)

CEI 패턴은 함수의 실행 순서를 조정하여 재진입 공격을 방지하는 방식이다.

| 단계 | 설명 |
|---|---|
| Checks | 사용자의 요청 및 잔액 확인 |
| Effects | 잔액 차감 등 내부 상태 갱신 |
| Interactions | 외부 컨트랙트 호출 및 자산 전송 |

외부 컨트랙트를 호출하기 전에 내부 상태를 갱신하기 때문에 공격자가 함수를 다시 호출하더라도 이전 상태를 악용하기 어렵다.

하지만 외부 호출의 결과에 따라 내부 상태를 갱신해야 하는 경우도 있기 때문에 모든 상황에서 CEI 패턴을 적용할 수 있는 것은 아니다.

#### Reentrancy Guard

Reentrancy Guard는 잠금장치를 이용하여 함수가 실행되는 동안 재진입을 제한하는 방식이다.

함수가 실행되면 잠금장치를 활성화하고, 실행이 완료되면 잠금장치를 해제한다. 잠금장치가 활성화된 상태에서 보호 대상 함수를 다시 호출하면 해당 요청이 차단된다.

이전에 분석했었던 Curve Finance 사건에서도 이러한 재진입 방지 장치가 사용되었지만, Vyper 컴파일러의 결함으로 인해 정상적으로 작동하지 않았다.

### 3.3. 기존 취약점 탐지 방식의 문제점

스마트 컨트랙트의 재진입 취약점을 자동으로 탐지하기 위해 Slither, Mythril, Securify 등 다양한 분석 도구가 개발되었다.

그러나 기존 탐지 도구는 CEI와 같이 잘 알려진 방어 패턴은 인식할 수 있지만, 상대적으로 잘 알려지지 않은 방어 패턴은 충분히 인식하지 못하는 문제가 있다.

이로 인해 실제로 안전한 컨트랙트를 취약하다고 판단하는 오탐(False Positive)이 발생한다.

| 구분 | 설명 |
|---|---|
| True Positive(TP) | 실제 취약점을 올바르게 탐지한 경우 |
| False Positive(FP) | 안전한 코드를 취약하다고 판단한 경우 |
| True Negative(TN) | 안전한 코드를 안전하다고 판단한 경우 |
| False Negative(FN) | 실제 취약점을 탐지하지 못한 경우 |

논문에서 인용한 선행 연구에서는 기존 탐지 도구가 보고한 재진입 취약점 중 90% 이상이 오탐으로 추정되었으며, 오탐을 검토하는 데 컨트랙트당 평균 약 30분이 소요된다고 설명했다.

따라서 실제 취약점을 탐지하는 것뿐만 아니라 불필요한 경고를 줄이는 것도 중요하다.

## 4. 핵심 아이디어

### 4.1. 방어 패턴을 중심으로 한 분석

기존 탐지 도구는 주로 재진입 공격이 발생할 가능성이 있는 코드 구조를 찾는 데 집중한다.

반면 본 논문에서는 **재진입을 방지하는 코드 패턴을 자동으로 식별하여 오탐을 줄이는 방식**을 제안했다.

개발자마다 재진입을 방지하기 위해 사용하는 코드의 구조나 구현 방식이 다르기 때문에 모든 방어 패턴을 사람이 직접 정의하는 데에는 한계가 있다.

이에 저자들은 실제 스마트 컨트랙트에서 사용되는 방어 패턴을 자동으로 학습하고 식별할 수 있도록 AutoAR이라는 시스템을 개발했다.

### 4.2. AutoAR의 역할

AutoAR은 기존 취약점 탐지 도구를 대체하는 것이 아니라 해당 도구의 분석 결과를 보완하는 시스템이다.

전체적인 동작 과정은 다음과 같다.

1. 기존 취약점 탐지 도구를 이용하여 재진입 취약점을 분석한다.
2. 취약점이 존재할 가능성이 있다고 판단된 컨트랙트를 AutoAR로 추가 분석한다.
3. 해당 컨트랙트에 재진입 방지 패턴이 존재하는지 확인한다.
4. 방어 패턴을 식별한 결과를 바탕으로 기존 탐지 결과를 개선한다.

기존 탐지 도구를 새롭게 개발하지 않고도 분석 성능을 개선할 수 있다는 점이 AutoAR의 특징이다.

## 5. 연구 방법론

### 5.1. AutoAR의 전체 구조

AutoAR은 크게 세 가지 핵심 요소로 구성되어 있다.

| 단계 | 설명 |
|---|---|
| Data Filtration | 재진입과 관련한 스마트 컨트랙트 선별 |
| RentPDG Construction | 재진입과 관련된 코드의 제어 및 데이터 의존 관계를 그래프로 표현 |
| Recognition Model | 그래프 학습과 군집화를 통해 유사한 방어 패턴 식별 |

AutoAR은 학습 단계에서 기존 컨트랙트의 방어 패턴을 학습하고, 식별 단계에서 분석 대상 컨트랙트에 학습한 방어 패턴이 존재하는지 확인한다.

### 5.2. Data Filtration(데이터 필터링)

모든 스마트 컨트랙트가 재진입 공격과 관련된 것은 아니기 때문에 학습에 필요한 컨트랙트를 먼저 선별한다.

외부 컨트랙트 호출과 내부 상태의 읽기 및 쓰기 연산이 존재하는 코드를 중심으로 재진입 공격과 관련된 컨트랙트를 찾는다.

또한 기존 탐지 도구가 비교적 잘 인식하는 CEI 패턴이 적용된 컨트랙트와 실제 재진입 공격 피해가 확인된 컨트랙트를 학습 대상에서 제외했다.

이를 통해 상대적으로 잘 알려지지 않은 재진입 방지 패턴을 중심으로 학습할 수 있도록 했다.

### 5.3. RentPDG Construction(그래프 구성)

스마트 컨트랙트에는 재진입 공격과 직접적으로 관련되지 않은 코드도 많이 포함되어 있다.

따라서 저자들은 재진입 방지 패턴과 관련된 정보를 효과적으로 추출하기 위해 RentPDG라는 그래프 표현 방식을 제안했다.

RentPDG는 기존 PDG(Program Dependency Graph)를 기반으로 한다.

| 의존 관계 | 설명 |
|---|---|
| Control Dependency(제어 의존성) | 특정 조건이 다른 코드의 실행 여부에 영향을 주는 관계 |
| Data Dependency(데이터 의존성) | 특정 변수의 값이 다른 연산에 영향을 주는 관계 |

RentPDG는 외부 호출과 관련된 코드의 의존 관계를 중심으로 정보를 추출한다. 또한 함수 간 호출 관계를 고려하여 실제로 실행될 수 없는 경로가 분석에 포함되는 문제를 줄인다.

이를 통해 불필요한 코드 정보를 줄이고 재진입 방지 패턴의 핵심적인 특징을 분석할 수 있게 된다.

### 5.4. Recognition Model(방어 패턴 식별 모델)

앞에서 생성한 RentPDG를 분석하기 위해 Graph Auto-Encoder와 Clustering을 사용한다.

- **Graph Auto-Encoder:** 그래프의 주요 특징을 수치화된 벡터로 표현하는 모델
- **Clustering(군집화):** 서로 유사한 특징을 가진 데이터를 같은 그룹으로 분류하는 방법

AutoAR은 그래프의 특징을 벡터로 변환한 뒤 유사한 특징을 가진 데이터들을 그룹으로 분류한다.

이후 새로운 컨트랙트가 입력되면 기존에 학습한 그룹과의 유사도를 비교하여 재진입 방지 패턴이 존재하는지 판단한다.

이러한 방식을 활용하면 모든 방어 패턴을 사람이 직접 정의하지 않아도 다양한 재진입 방지 패턴을 자동으로 식별할 수 있다.

## 6. 실험 및 평가 결과

### 6.1. 실험 데이터 및 평가 방법

저자들은 실제 이더리움 스마트 컨트랙트를 대상으로 AutoAR의 성능을 평가했다.

Etherscan을 통해 스마트 컨트랙트의 소스 코드를 수집했으며, 중복 데이터를 제거하여 총 115,240개의 컨트랙트를 확보했다.

(전체 데이터의 80%는 학습용으로, 나머지 20%는 테스트용으로 사용했다)

| 구분 | 개수 |
|---|---:|
| 전체 데이터셋 | 115,240개 |
| 학습 데이터 | 92,192개 |
| 테스트 데이터 | 23,048개 |
| 필터링을 통해 선별한 학습용 컨트랙트 | 34,081개 |

저자들은 AutoAR이 어떠한 방어 패턴을 식별할 수 있는지, 기존 탐지 도구의 오탐을 얼마나 줄일 수 있는지 등을 평가했다.

### 6.2. 재진입 방지 패턴 식별 결과

AutoAR은 실제 스마트 컨트랙트에서 사용되는 재진입 방지 패턴을 총 12종으로 분류했다.

(이 중에는 기존 연구에서 공개적으로 다루지 않았던 8종의 패턴도 포함되어 있었다)

| 평가 항목 | 결과 |
|---|---:|
| 식별한 재진입 방지 패턴 | 12종 |
| 기존 연구에서 공개적으로 다루지 않은 패턴 | 8종 |
| 평균 방어 패턴 식별 정확도 | 약 89% |
| 기존 탐지 도구의 오탐 감소율 | 약 85% 이상 |

저자들은 각 방어 패턴별로 30개의 컨트랙트를 선정하여 총 360개의 컨트랙트를 직접 검토했다.

그 결과 AutoAR은 각각의 방어 패턴에 대해 84% 이상의 식별 정확도를 보였으며, 전체적으로는 약 89%의 평균 정확도를 보였다.

이는 기존에 잘 알려진 방어 패턴뿐만 아니라 상대적으로 잘 알려지지 않은 방어 패턴도 자동으로 식별할 수 있다는 것을 보여준다.

### 6.3. 기존 탐지 도구와의 성능 비교

저자들은 AutoAR이 기존 취약점 탐지 도구의 성능을 얼마나 개선할 수 있는지 확인하기 위해 비교 실험을 진행했다.

실험에는 실제 재진입 취약점이 존재하는 컨트랙트 31개와 재진입 방지 패턴이 적용된 안전한 컨트랙트 298개가 사용되었다.

기존 탐지 도구에 AutoAR을 적용하기 전과 후의 오탐 건수를 비교한 결과는 다음과 같다.

| 탐지 도구 | 기존 오탐 | 적용 후 오탐 | 감소율 |
|---|---:|---:|---:|
| Slither | 211 | 21 | 90% |
| Securify | 129 | 16 | 88% |
| Mythril | 52 | 7 | 87% |
| Conkas | 158 | 24 | 85% |
| Smartian | 33 | 2 | 94% |
| Sailfish | 124 | 16 | 87% |

모든 탐지 도구에서 오탐이 약 85% 이상 감소했다. 특히 Smartian은 기존 33건의 오탐이 2건으로 감소하면서 약 94%의 감소율을 보였다.

또한 해당 실험에서는 AutoAR을 적용한 이후에도 기존 탐지 도구가 찾아낸 실제 취약점의 수가 감소하지 않았다.

### 6.4. 실험 결과에 대한 생각

실험 결과 AutoAR은 기존 도구가 찾아낸 실제 취약점은 그대로 탐지하면서도 오탐을 크게 줄일 수 있었다.

특히 모든 탐지 도구에서 오탐 감소 효과가 나타났다는 점이 인상 깊었다.

보안 분석가가 모든 취약점 경고를 직접 검토해야 한다면 많은 시간과 비용이 필요하지만, AutoAR을 활용한다면 실제 취약점에 더욱 집중할 수 있을 것이라고 생각했다.

기존 도구를 대체하지 않고 보완하는 방식이라는 점에서도 실용적인 연구라고 생각했다.

## 7. 한계점/아쉬운 점

AutoAR은 **기존 데이터**를 학습하는 방식이므로 새로운 방어 패턴을 정확하게 식별하지 못할 가능성이 있다고 생각했다. 또한 **소스 코드**를 분석하기 때문에 컴파일 과정에서 발생하는 결함까지 검증하기는 어려울 것이라 생각했다. 실제로 이전에 분석했었던 Curve Finance 사건에서도 방어 기능은 정상적으로 구현되어있었으나 컴파일러 문제로 해당 기능이 정상적으로 작동하지 않았고 큰 금전적 손실로 이어졌었다.

## 8. 마치며

### 8.1. 추가로 읽어보고 싶은 논문

[Empirical Review of Automated Analysis Tools on 47,587 Ethereum Smart Contracts](https://arxiv.org/abs/1910.10601)

기존 스마트 컨트랙트 분석 도구의 성능을 비교한 논문이다. 해당 논문을 읽고 도구마다 취약점 탐지 결과에 차이가 발생하는 이유를 알아보고 싶다.

### 8.2. 다른 분야에 적용하기

방어 패턴을 학습하여 오탐을 줄이는 방식을 웹 보안의 입력값 검증이나 임베디드 보안의 메모리 접근 검사에도 적용할 수 있을 것이라고 생각했다.

### 8.3. 직접 구현/재현하고 싶은 부분

재진입 방지 기능이 없는 컨트랙트와 CEI 패턴, Reentrancy Guard를 적용한 컨트랙트를 각각 구현해보고 싶다. 재진입 방지 기능이 없는 컨트랙트에서는 취약점이 탐지되고, 방어 패턴을 적용한 컨트랙트에서는 취약점이 탐지되지 않을 것으로 예상한다. 하지만 논문에서 언급한 것처럼 방어 패턴을 적용했음에도 오탐이 발생할 수 있으므로, 실제로 예상과 일치하는지 Slither 등의 분석 도구를 활용하여 탐지 결과를 비교해보고 싶다.

### 8.4. 연구/프로젝트로의 심화

기존 Curve Finance 사고 분석과 이번 논문을 연결하여 소스 코드와 바이트코드를 함께 분석하는 보안 검증 시스템을 구현해보고 싶다. 특히 Vyper 컴파일러 버전에 따라 재진입 방지 장치의 동작이 어떻게 달라지는지 확인하고, 컴파일러 결함으로 인한 취약점까지 탐지할 수 있는 방향으로 발전시키고 싶다.

## 9. 느낀점/결론

기존에는 보안 분석에서 취약점을 발견하는 것이 가장 중요하다고 생각했었다. 하지만 이번 논문을 통해 오탐을 줄이는 것 또한 분석의 효율성을 높이는 데 중요하다는 것을 알게 되었다.

특히 공격 패턴이 아닌 방어 패턴에 집중하여 기존 탐지 도구의 한계를 개선했다는 점이 인상 깊었고 이전에 분석했었던 Curve Finance 사건과 연결하여 생각해볼 수 있어서 좋았다.

앞으로는 스마트 컨트랙트 분석 도구를 직접 사용해보고, 방어 방식과 컴파일러 버전에 따른 탐지 결과 및 실제 실행 동작의 차이를 공부해보고 싶다.
